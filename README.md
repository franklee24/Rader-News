# 雷达新闻（Rader-News）

> 一个面向个人信息获取的 **全球核心新闻雷达系统**。
>
> 自动聚合全球新闻源，按国家和梯队组织新闻，在固定时间窗口内完成抓取、过滤、事件去重、重要性评分和网页发布。

**在线地址：** https://franklee24.github.io/Rader-News/

---

## 一、项目是做什么的？

雷达新闻不是简单的 RSS 阅读器，而是一套每天自动运行的全球新闻筛选系统。

它解决的是一个核心问题：

> **每天只花几分钟，快速知道过去24小时全球哪些事情真正值得关注。**

系统每天以**北京时间 08:00**为日报分界点，生成上一周期的新闻：

```text
前一天 08:00
      ↓
   24小时新闻窗口
      ↓
新闻源采集
      ↓
国家识别 / 梯队归类
      ↓
无效新闻过滤
      ↓
同一事件多源聚合
      ↓
上一日报去重
      ↓
事件重要性评分
      ↓
按国家展示
      ↓
GitHub Pages 自动发布
```

### 2. 固定24小时新闻窗口

系统不是简单地“运行时往前取24小时”。

日报严格按照北京时间 08:00 划分：

```text
今天日报：昨天 08:00 → 今天 08:00
明天日报：今天 08:00 → 明天 08:00
```

因此，即使 GitHub Actions 因负载在 08:00 后几分钟才开始运行，也不会把窗口向后移动。

这也是项目避免“昨天新闻混进今天日报”的核心机制之一。

---

### 3. 多源新闻采集

系统不是依赖单一媒体。

新闻源可以包括：

- 国际通讯社
- 各国主流媒体
- 财经媒体
- 科技媒体
- 政府、央行及国际组织公开信息
- Google News / Bing News 等聚合 RSS

来源选择遵循一个原则：

> **优先权威、优先原始报道、优先当地媒体。**

对于国外国家：

- 如果当地媒体有**中文版**，优先使用中文版；
- 如果没有中文版，则使用**英文版**；
- 不主动使用法语、德语、俄语、日语等用户无法直接阅读的原文。

例如：

```text
美国 → 美国主流媒体 / 国际通讯社
英国 → BBC / Guardian 等英国媒体
日本 → 日本媒体的英文版
德国 → 德国媒体的英文版
俄罗斯 → 俄罗斯媒体的英文版
```

同一事件如果有多个媒体报道，系统会尝试聚合，而不是把一件事重复显示多次。

---

### 4. 同一事件去重

这是雷达新闻与普通 RSS 阅读器的重要区别之一。

例如：

```text
Reuters：某国宣布新关税政策
BBC：某国宣布新关税政策
AP：某国宣布新关税政策
当地媒体：某国宣布新关税政策
```

系统希望最终展示为：

```text
某国宣布新关税政策

来源：Reuters / BBC / AP / 当地媒体
```

而不是把同一事件显示四次。

同时，系统还会与**上一日报**进行去重，避免用户昨天已经看到的新闻今天再次作为新新闻出现。

---

### 5. 严格新闻时间过滤

每条新闻必须尽可能具有明确的发布时间。

如果新闻没有可靠的发布时间，系统会将其视为不适合进入严格日报窗口的数据并过滤掉。

目标是：

> **宁可少，也不拿无法确认时间的旧新闻凑数量。**

---

### 6. 事件重要性评分

新闻右上角显示的数字是**事件重要性评分**，满分100分。

当前评分不再只是简单统计关键词，而是综合考虑事件本身的影响。

主要维度：

| 维度 | 权重 |
|---|---:|
| 影响范围 | 25 |
| 事件严重性 | 20 |
| 战略 / 政策影响 | 20 |
| 国家战略地位 | 15 |
| 未来72小时影响 | 10 |
| 多源验证 | 5 |
| 时效性 | 5 |
| **总分** | **100** |

### 重要性等级

| 分数 | 等级 | 含义 |
|---:|---|---|
| 90–100 | ★★★★★ | 全球重大 |
| 80–89 | ★★★★ | 国家重大 |
| 70–79 | ★★★ | 重要事件 |
| 60–69 | ★★ | 值得关注 |
| 0–59 | ★ | 一般动态 |

评分的目标是回答：

> **这件事情到底有多值得我现在关注？**

而不是单纯判断“这篇文章有多热门”。

## 三、每天什么时候自动更新？

GitHub Actions 使用 UTC 时间。

生产环境配置为：

```yaml
schedule:
  - cron: '0 0 * * *'
```

因此对应：

> **北京时间每天 08:00 自动运行。**

GitHub Actions 受平台调度影响，实际开始时间可能存在几分钟延迟，因此实际使用时应理解为：

> **每天北京时间 08:00 左右更新。**

同时保留：

```yaml
workflow_dispatch
```

因此也可以在 GitHub Actions 页面手动运行。

## 四、新闻数量规则

新闻数量是**目标 / 上限**，不是硬性凑数要求。

### 第一梯队

每国目标约 20–30 条。

### 第二梯队

每国最多约 20 条。

### 第三梯队

每国最多约 15 条。

### 第四梯队

每国最多约 10 条。

### 全球补充

约 10 条。

如果过去24小时真正发生的重要事件不足：

> **不使用旧新闻、不重复事件、不人为制造新闻凑数量。**

因此某个国家出现10条甚至更少，是允许的。

## 六、失败保护机制

系统设计目标是：**单个新闻源失败不能导致整套系统停止。**

### 一个新闻源失败

继续使用其他新闻源。

### 一个国家的新闻源失败

其他国家继续运行。

### RSS 返回 429 / 请求失败

进入备用来源，不进行无意义的长时间重复请求。

### 整轮没有有效新闻

阻止发布空白数据，并尽可能保留上一份成功快照。

### 新闻没有可靠发布时间

不让其进入严格日报时间窗口。

## 十一、如何修改新闻来源

新闻源相关逻辑主要位于：

```text
scripts/build_daily.py
```

建议新增来源时遵循：

1. 优先官方 / 原始来源
2. 优先国际通讯社和主流媒体
3. 优先当地媒体
4. 用户能直接阅读
5. 尽量提供真实原文直达链接
6. 同一事件不要制造多个新闻位

## 十二、设计原则

雷达新闻遵循几个核心原则：

### ① 宁缺毋滥

没有重要新闻，就少发。

### ② 新闻优先

日报严格围绕固定的北京时间 08:00 时间窗口。

### ③ 事件优先

同一事件多个媒体报道，应尽量合并成一个事件。

### ④ 权威优先

优先使用可靠、权威、信息完整的新闻源。

### ⑤ 当地视角

对于国外新闻，适当吸收当地媒体信息，而不是只依赖中文二手报道。

### ⑥ 可读优先

不使用用户无法阅读的非必要原文语言。

### ⑦ 重要性优先

新闻排序的最终目标不是“新闻最多”，而是：

> **最重要的事情排在最前面。**
